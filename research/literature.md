## 一、奠基与架构：世界模型到底在预测什么

| 论文 | 编号 / 时间 | 一句话要点 | 与岗位的关系 |
|---|---|---|---|
| **World Models** | [1803.10122](https://arxiv.org/abs/1803.10122) · 2018 | V（看）→ M（在压缩潜空间里做梦）→ C（据此行动）三段式 | 今天所有 latent 预测路线的源头；理解「为什么要在潜空间而非像素空间预测」是讨论数据粒度的前提 |
| **DreamerV3** | [2301.04104](https://arxiv.org/abs/2301.04104) · 2023 | 同一套超参跨 150+ 领域，证明世界模型做 RL 的可扩展性 | 「世界模型要有决策效用」这一档的证据来源，对应证据阶梯第 4 档 |
| **Cosmos World Foundation Model Platform** | [2501.03575](https://arxiv.org/abs/2501.03575) · 2025 | NVIDIA 的全模态世界基础模型平台：数据管线 + 护栏 + 后训练 | 最像「岗位日常工作」的公开参照：数据策展、安全护栏、后训练都写在里面 |
| **V-JEPA 2** | [2506.09985](https://arxiv.org/abs/2506.09985) · 2025-06 | 自监督视频表征即可支撑理解、预测与规划；62 小时机器人数据完成动作对齐 | 「小数据 + 好表征」路线：这类模型对标注质量极敏感，是数据岗的价值放大器 |
| **V-JEPA 2.1** | [2603.14482](https://arxiv.org/abs/2603.14482) · 2026-03 | 解锁 dense feature，表征更细粒度 | 同上：表征越细，跨帧一致性标注的收益越大 |

**我的读法**：这一组回答「预测发生在哪个空间」。像素空间预测的画面好看但难控；潜空间预测省算力却可能丢细节——**数据侧的分层（L0 原始素材 / L1 结构化标注 / L2 交互轨迹 / L3 失败样本）本质上就是在给不同层级的预测目标准备不同粒度的监督信号**。

## 二、交互生成：从「生成一段视频」到「生成一个可行动的世界」

| 论文 | 编号 / 时间 | 一句话要点 | 与岗位的关系 |
|---|---|---|---|
| **Genie: Generative Interactive Environments** | [2402.15391](https://arxiv.org/abs/2402.15391) · 2024-02 | 从无标注互联网视频学出 latent action，生成可操控的 2D 世界 | 关键启示：**动作标签可以从数据里学出来，也可以标注出来**——后者正是 L2 交互轨迹层存在的理由 |
| **GameNGen** | [2408.14837](https://arxiv.org/abs/2408.14837) · 2024-08 | 扩散模型当实时游戏引擎，单 GPU 可玩 DOOM | 证明「实时可玩」不一定要神经 3D 表示；也提示长时程误差累积是硬伤 |
| **DIAMOND** | [2405.12399](https://arxiv.org/abs/2405.12399) · 2024-05 | 扩散式世界模型在 Atari 上的保真度优于离散 token 方案 | 视觉细节影响 RL 表现 → 反推「细节丢失」也该是可标注的故障类型 |
| **Navigation World Models** | [2412.03572](https://arxiv.org/abs/2412.03572) · 2024-12 | 条件扩散做视觉导航轨迹规划 | 相机/路径可控性的学术版本，对应我影视分镜那条评测线 |
| Genie 2 / Genie 3 | 官方博客（无 arXiv）· 2024-12 / 2025-08 | 单 prompt 生成可玩 3D 世界；Genie 3 达 24fps 实时交互 + promptable world events | 我评测台里「世界事件注入」的直接灵感来源 |

**我的读法**：这一组回答「用户能做什么」。评测维度必须跟着控制接口走——**能导航的世界测空间与拓扑，能下指令的世界测事件持续性，只能出片的世界测镜头与一致性**。用同一套指标测三种接口，必然误判（这也是我在 SKILL 里写「不同任务类型用不同维度子集」的依据）。

## 三、评测基准：这一档最贴近岗位（重点）

| 论文 | 编号 / 时间 | 测什么 | 给我的启发 |
|---|---|---|---|
| **Reading, Writing, Sharing, and Interacting with the World through Video**（牛津等校，102 页综述） | [2610.31668](https://arxiv.org/abs/2610.31668) · 2026-10-22 | 读 / 写 / 共享 / 交互四种操作；**证据阶梯**：合理输出 → 忠实条件 → 一致世界状态 → 决策效用 | 我的打分卡对齐第三档「一致世界状态」；评低分先问证据在哪一档 |
| **RoboWM-Bench** | [2604.19092](https://arxiv.org/abs/2604.19092) · 2026-04 | 把生成视频转成动作序列、进物理仿真执行，验证具身可执行性 | **视觉合理 ≠ 做得到**——这是「故障标签绑定数据回流而非分数」的依据 |
| **EWMBench** | [2505.09694](https://arxiv.org/abs/2505.09694) · 2025-05 | 具身世界模型：场景一致性 / 运动质量 / 语义对齐 | 三分开打分，不合并成总分——与我 8 维分列的思路一致 |
| **WBench** | [2605.25874](https://arxiv.org/abs/2605.25874) · 2026-05 | 多轮交互式视频世界模型评测 | 证明「多轮」需要单独设计，单轮指标会掩盖累积漂移 |
| **WorldRoamBench** | [2606.31672](https://arxiv.org/abs/2606.31672) · 2026-06 | 开放世界长时程稳定性 | 与我任务卡 1「房间回访」（离场 → 返回）同源，回访距离与状态保持要分开变量 |
| **WorldSimBench** | [2410.18072](https://arxiv.org/abs/2410.18072) · 2024-10 | 视频生成模型当世界模拟器的能力 | 人类偏好打分 + 感知/操作双评——主观与客观分开报告 |
| **WorldModelBench** | [2502.20694](https://arxiv.org/abs/2502.20694) · 2025-02 | 判定视频生成模型「算不算」世界模型 | 与证据阶梯同题不同解，可对照着读 |
| **ACT-Bench** | [2412.05337](https://arxiv.org/abs/2412.05337) · 2024-12 | 自动驾驶场景下的动作可控性 | 「给了动作，画面照做没有」——对应 L2 的（指令， 执行结果）配对数据 |
| **World Model for Robot Learning: A Comprehensive Survey** | [2605.00080](https://arxiv.org/abs/2605.00080) · 2026-04 | 机器人学习视角的世界模型综述 | 看「下游任务怎么反过来定义上游数据需求」 |

**我的读法**：这一组是本套件 8 维维度、L0–L3 分层、3 张任务卡的**公开出处**。面试时如果需要辩护"为什么是这 8 维、为什么要分层"，可以直接对到这几篇。

## 五、我会在面试里主动提出的三个开放问题

1. **一致性 vs 实时性冲突时先保哪个？** 我的倾向是先保一致性——一个记不住上一秒的世界，交互本身就没意义。但实时性低于某个阈值时交互也不成立，这个阈值需要实验定。
2. **影视级镜头数据自建拍摄，还是从现有素材反推相机参数？** 后者成本低但精度存疑，直接决定相机可控性的上限（相关工作：Navigation World Models 的路径条件化思路可借鉴）。
3. **自动指标会聚集，人评会漂移，怎么校准？** RoboWM-Bench 已经证明视觉分数会聚集；我的做法是让人工分与规则法自动预估并列、差异 ≥1 分时强制复查标注定义——但抽检比例怎么定才不引入系统性偏差，我没有答案。
