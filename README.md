# World Model Data Kit

**世界模型训练数据：从场景拆解，到评测闭环**

> 作者：梁爽（中国传媒大学 国际新闻学硕士 / 广播电视学本科）· 2026.10
> 一页纸调研 + 一个可运行的评测原型。为「世界模型训练产品（AI数据与安全）」岗位而做。
>
> **证据边界**：两个 JSON 样例都是人工构造的示意输入，不是模型输出；工具仅按手工整理的元数据做探索性分档，不读取视频。阈值、目标时延与复核线未校准，没有多人一致性或真实模型基准结果。当前作品展示的是流程假设，不是已验证 benchmark。

## 1. 一个判断

一个可检验的产品假设是：对于交互式世界模型，除画面外观外，还应评估「**能不能控、状态能否持续、动作是否产生一致后果**」。结构化观测（例如相机轨迹、跨帧物体 ID、动作与后续状态）可能帮助定位数据缺口；它们对模型能力的实际收益需要实验验证。

因此本项目聚焦两项待验证的产品问题：标注 schema 是否能稳定表达任务约束，以及评测失败能否转成可执行的数据补充动作。

## 2. 场景拆解：数据需求从哪里来

| 场景 | 关键环节 | 当前痛点 | AI 介入点 | 对应数据需求 |
|---|---|---|---|---|
| 影视 | 分镜预览 / 预演 | 分镜沟通成本高、改镜贵 | 文本、草图 → 可交互分镜 | 镜头语言（景别 / 运镜 / 轴线）+ 多机位一致性 |
| 影视 | 特效与场景延展 | 绿幕与重绘成本高 | 局部重绘、场景扩展 | 局部编辑前后对 + 遮罩标注 |
| 游戏 | 关卡与场景原型 | 原型迭代慢 | 世界生成 → 可玩原型 | 可通行性、碰撞标注 + 相机—动作对 |
| 游戏 | NPC 行为 | 行为树写死、泛化差 | 动作条件生成 | `(state, action) → next_state` 轨迹三元组 |
| 具身 | 机器人操作 | 真实采集昂贵 | 世界模型内预训练 | 操作前后状态变化 + 失败案例 |

**当前假设**：影视侧更常关注「镜头控制 + 局部编辑」，游戏与具身侧更常关注「动作条件轨迹」。具体 schema 应按用户任务验证；可共享底层来源与治理字段，不预设必须拆成完全独立产线。

## 3. 建议的数据加工阶段

- **L0 原始素材** — 长视频、多机位、保留拍摄元信息
- **L1 结构化标注** — 相机参数轨迹、跨帧物体框与 ID、事件/动作标签、物理合理性标记
- **L2 交互轨迹** — `(state, action) → next_state` 三元组，带时间戳与响应延迟
- **L3 归因与学习用途** — 经复核的失败链、偏好对或 hard negative；记录证据与用途，不表示所有失败都自动属于 L3。

L0–L3 在这里表示**加工阶段建议**，不等于质量等级或样本种类。`positive`、`negative`、`preference_pair`、`trajectory` 等样本类型应单独记录；同一条数据可以既有 L1 结构化标注，也被纳入 L3 失败链。

## 4. 评测维度（8 项）

| 维度 | 怎么测 | 失败长什么样 |
|---|---|---|
| 时空一致性 | 同一场景多次回访，比对静态元素 | 墙上的画，第二次进去变了 |
| 物体恒存 | 遮挡后再出现，比对属性 | 藏起来的杯子回来变成别的颜色 |
| 物理合理性 | 碰撞 / 支撑 / 流体检查 | 杯子穿过桌面 |
| 相机控制精度 | 给定运镜指令，比对轨迹误差 | 「左移环绕」做成了平移 |
| 动作 / 指令跟随 | 指令—结果人工比对 | 「把门打开」没被执行 |
| 交互延迟 | 在固定环境记录端到端响应时延，并对照场景目标 | 超过该任务预先设定的目标；目标需按运行环境与产品体验确定 |
| 长时记忆与因果 | 多步操作后回溯前序状态 | 第三步时忘了第一步挪过椅子 |
| 局部可编辑性 | 局部重绘后检查周边一致性 | 改了沙发，地板光影穿帮 |

## 5. 三张评测任务卡（完整版见 `taskcards/`）

1. **房间回访** — 进 A 房间放 3 个物体 → 离开 → 按任务参数返回（30 秒仅为候选示例），检查物体恒存与空间一致性
2. **镜头指令还原** — 给一段分镜指令（景别 + 运镜 + 时长），比对生成结果的相机轨迹误差
3. **因果与记忆链** — 三步连续操作（挪椅子 → 开门 → 放包），最后提问「椅子最初在哪」

## 6. 闭环：把评测结果翻译成采集动作

我写了一个可运行的评测原型 `eval_kit/score.py`：输入人工整理的样本元信息，按未校准的规则输出维度探索性分档、观测覆盖率和复核建议。它不会自动判断视频内容，也不会据此断言样本“可用”或模型“高质量”。

这是本项目希望验证的一环：评测记录能否帮助团队定位下一步数据补充方向。是否能降低成本或改善模型表现，需要在实际流程中验证。

```bash
python eval_kit/score.py eval_kit/samples/clip_A_interactive.json
```

输入字段和“已评 / 未评 / N/A”定义见 [`eval_kit/schema.md`](eval_kit/schema.md)。样例输入均为合成示意，解释边界见 [`eval_kit/output_example.md`](eval_kit/output_example.md)。

## 7. 我还不确定、想跟团队聊的

- **一致性与实时性冲突时先保哪个？** 我的倾向是先保一致性——一个记不住上一秒的世界，交互本身就没有意义。
- **影视级镜头语言数据自建拍摄，还是从现有影视素材反推相机参数？** 后者成本低，但精度存疑，会直接影响相机可控性上限。
- **L3 失败样本标注成本很高**，能否用「模型自评 + 人工抽检」降本？抽检比例怎么定才不引入系统性偏差？

### A3. Genie 3 官方局限 → 评测任务映射

Genie 3 博客自己承认的五个局限，每条都是一张可设计的评测任务卡：

| 官方局限 | 评测任务卡设计 | 数据回流 |
|---|---|---|
| 动作空间受限 | 固定世界、遍历动作集合，测哪些动作真的生效 | L2：可交互物清单 + 触发条件标注 |
| 多智能体交互难 | 双角色协作任务（递物 / 让路），测互不干扰且因果正确 | L1+L3：双主体 ID 对齐 + 失败链入库 |
| 真实地理位置失真 | 用真实地标 prompt，对比可识别参照物的方位与比例 | L1：地标锚点标注 |
| 文字渲染不稳 | 场景内固定文案（招牌/字幕）跨帧读取一致性 | L1：文本区域跨帧 ID |
| 连续交互仅数分钟 | 房间回访（离场 → 绕路 → 回到原房间），测状态与拓扑 | L3：记忆丢失失败链 |

（前两条对应本仓库 `taskcards/eval_task_cards.md` 已有的任务卡 1–3；后三条是新映射。）

### A4. 对一页纸核心判断的更新

待验证的产品判断：不同交互任务对一致性、响应速度和控制精度的取舍不同；仅凭通用维度分数不足以证明“数据是护城河”。需要用任务成功率、专家判断和迭代前后对照来验证评测与回流的实际价值。
